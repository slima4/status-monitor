# Support

This page covers the hosted service at `uptimepage.dev`.

## Where to write

| Reason | Where |
|---|---|
| Anything about your account or the hosted service | the **get help** form in the app, or <hello@uptimepage.dev> |
| Security vulnerabilities | <security@uptimepage.dev>, subject `[SECURITY]` |
| Questions and feature requests | [GitHub discussions](https://github.com/uptimepage/uptimepage/discussions) |
| Bugs in the product | [GitHub issues](https://github.com/uptimepage/uptimepage/issues) |
| Abuse from a monitor or status page we host | <hello@uptimepage.dev>, see the [Abuse Policy](https://uptimepage.dev/abuse-policy) |

The help form is the fastest route if you are signed in: it attaches your organization, plan and the page you were on, so there is nothing to describe twice. It replies to the address on your account.

Please do not report vulnerabilities through GitHub issues or discussions. The [Security Policy](https://uptimepage.dev/security-policy) has the disclosure timeline and what is in scope.

## What to include

If you used the help form, quoting the reference it showed you takes us straight to your request. Otherwise a monitor or organization name gets us to the right data quickly. If a check is behaving in a way you did not expect, the monitor name, roughly when it happened, and what you expected instead is usually enough. If the API or an integration returned an error, send the whole error response and the request that produced it.

## Service level

We run the hosted service on a best-effort basis. There is no service-level agreement, no uptime guarantee, and no financial credits for downtime. If you need a contractual guarantee, run your own instance, where the availability is yours to engineer, or write to us about a custom arrangement.

Planned maintenance is posted on [our own status page](https://uptimepage.uptimepage.dev), which runs on this product.

## Status of the service itself

Our status page is a normal uptimepage status page, monitored by a separate instance, so an outage here does not take the status page with it. Subscribe there if you want to be told before you notice.

## Self-hosting

If you run your own instance, support is [GitHub discussions](https://github.com/uptimepage/uptimepage/discussions) for questions, the issue tracker for bugs, and the [Troubleshooting](../troubleshooting.md) page. We read every issue, but we do not run your instance and cannot see your data. Include your version, your deployment shape, and the relevant log lines.
